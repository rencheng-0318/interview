# 临床记录语义搜索 — 需求文档

---

## 一、产品概述

### 1.1 产品定位

构建一个端到端的**临床记录语义搜索**功能。用户输入自然语言描述（如"反复头痛，伴随闪光、恶心和畏光"），系统返回其**所属诊所（practice）** 中语义相关的患者列表，并附带匹配的具体文档和段落。

### 1.2 核心原则

- 这是一个**检索（retrieval）** 功能
- **禁止**生成诊断、推断记录中不存在的病症
- **禁止**将相似度分数呈现为临床置信度

## 三、需要实现的功能模块

### 3.1 可搜索表示层（数据库 Schema 设计）

**入口**: `database/migrations/0002_*.sql`

**需求**:
- 设计并迁移用于语义检索的数据库表示（chunk + embedding 存储）
- 保留足够的源文档元数据，支持：
  - 诊所隔离（practice isolation）
  - 患者级别的结果聚合
  - 证据溯源（source evidence）
  - 源文档变更时的安全更新
- 需解释重要的约束、索引和生命周期决策

### 3.2 索引工作流（Indexing Workflow）

**入口**: `services/api/app/features/indexing/` + `app/scripts/index_clinical_documents.py`

**命令**: `make index`

**功能需求**:
1. 将源文档通过嵌入服务处理为可搜索的向量表示
2. **幂等性**：重复运行不得重复未变更的索引内容
3. **增量更新**：源文档的相关变更需被反映，无需完全手动重置
4. **容错性**：单个不可索引文档不得破坏整体索引
5. **可观测性**：报告足够的完成信息以诊断成功和失败

**设计决策（需论证）**:
- 内容分段（chunking）策略
- 变更检测机制
- 持久化方式
- 失败处理策略

### 3.3 语义搜索 API

**入口**: `services/api/app/features/search/router.py`

**端点**: `POST /api/clinical-search`（当前返回 501）

**请求 Schema** (`ClinicalSearchRequest`):
```python
query: str                          # 自然语言查询
document_types: list[DocumentType] | None  # 可选文档类型过滤
limit: int | None                   # 可选结果数量限制
```

**响应 Schema** (`ClinicalSearchResponse`):
```python
query: str
results: list[SearchResult]   # 每项含 patient + best_match + additional_matching_documents
meta: { result_count, took_ms }
```

**功能需求**:
1. 验证请求（query 长度上限 500 字符，limit 默认 10，最大 25）
2. 使用**向量语义检索**（非纯关键词匹配）
3. 结果**严格限制**在认证用户当前诊所内
4. 返回排序列表，**每位患者最多出现一次**
5. 每个患者结果必须包含**支持性源文档证据**（snippet）
6. 无索引或无匹配时行为可预测
7. 依赖故障时返回有用的客户端安全错误

**安全约束**:
- 客户端**不得**选择或覆盖诊所标识符
- 诊所隔离必须在**可信后端检索边界内**强制执行

**错误响应**:
- 422: 请求验证失败
- 503: 依赖服务不可用（如嵌入服务故障）

### 3.4 搜索前端体验

**入口**: `apps/web/app/search/page.tsx` + `apps/web/features/search/`

**功能需求**:
1. 用户可输入并提交自然语言查询
2. 可选按文档类型过滤（`diagnostic_note`, `specialist_note`, `radiology_report`, `lab_report`）
3. 展示排序的患者级别结果列表
4. 每条结果展示：
   - 患者信息
   - 源文档标题、类型、日期
   - 匹配摘录（snippet）
   - 额外匹配文档数量提示
5. 可导航至已有的患者详情页 `/patients/[patientId]`

**状态处理**:
- 空闲（idle）
- 加载中（loading）
- 有结果（results）
- 无结果（no-results）
- 输入无效（invalid-input）
- 依赖故障（dependency-failure）

**技术约束**:
- 通过 Server Action 或 route handler 提交，**禁止**浏览器直接调用 API
- 服务端配置和凭证不得暴露到浏览器代码
- 相关度分数不得标注为"置信度"、"概率"或"临床确定性"

### 3.5 运维可观测性

- 提供足够的诊断信息以调查索引和搜索故障
- **禁止**日志记录：文档正文、支持段落、患者姓名、嵌入向量

## 四、嵌入服务约束（已提供，不可修改）

| 属性 | 值 |
|---|---|
| 模型 | `sentence-transformers/all-MiniLM-L6-v2` (ONNX) |
| 向量维度 | 384 |
| 向量归一化 | L2 归一化 |
| 最大序列长度 | 256 tokens（超出截断） |
| 每请求最大文本数 | 64 |
| 每文本最大字符数 | 8,000 |
| 空白输入 | 拒绝（422 `blank_text`） |
| 确定性 | 相同输入产生相同输出 |

**错误码**:
- 422 `blank_text`: 空或纯空白文本
- 422 `text_too_long`: 超过字符限制
- 422 `batch_too_large`: 超过 64 条
- 503 `injected_failure`: 故障注入

## 五、数据集说明

| 维度 | 数值 |
|---|---|
| 诊所数 | 3 |
| 患者数 | 715 |
| 文档数 | 2,400 |
| 文档类型 | `diagnostic_note`, `specialist_note`, `radiology_report`, `lab_report` |

- 数据为确定性合成数据，`make seed` 可重复加载
- 文档长度、格式和内容质量存在现实变化
- 不可假设每份文档都适合索引
- 不可假设最强语义匹配一定属于当前诊所
- 实现不得依赖硬编码记录标识符或数据集排序

## 六、安全与隐私要求

1. 不得将记录发送至未经批准的外部服务
2. 不得提交凭证或本地环境文件
3. 不得通过搜索请求暴露诊所选择
4. 摘录足够时不得返回完整文档
5. 不得在日志中记录文档内容、患者姓名、摘录或向量
6. 不得向客户端暴露堆栈跟踪或数据库驱动细节

## 十、技术架构概览

```
用户 -> Next.js 16 (App Router, Tailwind v4)
         -> Server Action / Route Handler
              -> FastAPI (POST /api/clinical-search)
                   -> 嵌入服务 (查询向量化)
                   -> PostgreSQL + pgvector (向量相似度检索)
                   -> 结果聚合 + 诊所隔离
              <- 排序的患者结果 + 证据
         <- 渲染搜索结果 UI
```

**关键配置参数**:
- `SEARCH_DEFAULT_LIMIT`: 10
- `SEARCH_MAX_LIMIT`: 25
- `SEARCH_MAX_QUERY_LENGTH`: 500
- `EMBEDDING_MAX_BATCH_SIZE`: 64
